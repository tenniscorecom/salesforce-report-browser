# salesforce-report-browser

**本体の取り残しを、ブラウザでまとめて落とすバッチ。**

本体（Salesforceレポートダウンローダー）は Salesforce のレポートを Report API /
SOQL で取り、管理表（レポート管理表.xlsx）に従って保存・履歴記録する。
このリポジトリは **本体の後に実行** して、**本体が取り残した行を全部ブラウザで
取る**（画面上のエクスポート機能を使うので、2000 件超のレポートも取れる）。

管理表・保存先・履歴・排他はすべて本体が持つ。このリポジトリは本体の
`download_scheduled()` に「1 件取りに行く関数」を渡すだけ（管理表・履歴の写しは
持たない）。

```
本体（Report API / SOQL）を実行
        ↓
このリポジトリを実行 ← 当日まだ取れていない行を全部ブラウザで取る
```

## 初回の準備

1. **config.ini を作る。** `config.ini.example` を `config.ini` にコピーして、
   `[DOWNLOADER] PATH` に本体のフォルダ（Salesforceレポートダウンローダー）を書く。
2. **認証情報を登録する。** `認証情報の登録.bat` を実行し、ブラウザで使う
   **ID とパスワード** を登録する（`python -m comken cred gui` の画面）。
   MFA の承認はスマホでします。

## 実行方法

```bat
実行.bat
```

- **MFA はスマホで承認する。** ブラウザはログインしたあと承認を待ちます。
  无人だとログインできず、そのレポートは失敗として履歴に残ります。
- **同時実行すると、後から起動した方は取得せずに黙って終わる。** 本体の排他が
  効いているので Salesforce へ二重に取りに行きません（ログに 1 行出て終了）。
- 組織ごとにブラウザは 1 つだけ使い回します。ログインも組織ごとに 1 回だけです。
  途中で失敗したブラウザは閉じて、次のレポートでは開き直します。

## 開発

```bat
python -m pytest -q           :: テスト（ブラウザ・Salesforce には接続しない）
python -m ruff check .        :: リント
python -m ruff format --check .  :: 書式
```

ブラウザ操作・ログイン・使い回しは `browser_report/fetch.py`、
実行の入口は `browser_report/run.py` にある。
